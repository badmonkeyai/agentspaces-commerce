# agentspaces-commerce changelog

What changed in the commerce records, the verification of a mandate's credential chain, and the JOSE layer, newest first.

## Unreleased: 0.6.0

The first release of agentspaces-commerce on Maven Central, from its own repository. It builds on the AgentSpaces 0.6.0 core.

- **The records (2026-11-05).** `Mandate` carries an Agent Payments Protocol (AP2) Checkout or Payment Mandate as an entry of a group's `commerce` space: its kind, the role that wrote it, the `Cart`, the counterparty, the `Basis` a shopper's mandate rests on, the credential as issued (its public parts only), and its state. `Order` carries the Universal Commerce Protocol (UCP) order a mandate led to, with the UCP status, the fulfillment, and the permalink. `Cart` holds at most 64 items in ISO 4217 minor units. Every record is version 1, and each constructor refuses an unknown kind, role, state, or status.
- **The verification (2026-11-05).** `Mandates.verify` checks a credential chain with no policy and no network: the issuer-signed ES256 JWT under a trusted `kid`, the AP2 `vct`, the expiry, a closed checkout mandate's `checkout_hash` over the merchant-signed `checkout_jwt` (which it also verifies), a payment mandate's `transaction_id` and amount, and the key-binding JWT under `cnf.jwk` with its `sd_hash`. A `Verdict` names the first check that failed.
- **The reserved names (2026-11-05).** The core's `Reserved` in `agentspaces-api` holds `aspace:cap/commerce` with the roles `merchant`, `shopper`, and `payment`, the parameters `profile`, `ucp`, and `jwk`, and the `commerce` space. The AgentSpaces specification v0.1.27 describes them (SPEC §7.6 and §8), and nothing changed on the frame wire.
- **Pinned bytes (2026-11-05).** Three golden CBOR vectors pin the records: `mandate_cbor`, `order_cbor`, and `capability_commerce_cbor`. The Python client (`agentspaces.commerce`), the TypeScript client (`commerce.ts`), and the Clojure bindings (`agentspaces.commerce`) carry twins that round-trip the same vectors byte for byte.
- **JOSE and JSON on Nimbus and Jackson (2026-11-06).** `Jose` became a wire-compatible layer over Nimbus JOSE + JWT, and the claim sets' JSON moved to Jackson (insertion order on write, longs for integral numbers). The hand-rolled JWS and JSON code went, and the API stayed the same: `sign`, `parse`, `verify`, `toJwk`, `fromJwk`, `digest`, and `generateP256`. `JoseTest` shows that a JWT signed here verifies under Nimbus directly and the other way round. The library gained two compile dependencies, `nimbus-jose-jwt` and `jackson-databind`, both at the versions the `agentspaces-dependencies` BOM manages.
- **The repository (2026-11-10).** The README opens with a quick start that we compiled and ran: a merchant and a user sign a checkout mandate, and `Mandates.verify` checks it under two trust maps. Beside it are the documents under `docs/` (records, verification, building, releasing), the contributing guide, the security policy with what the check does and does not cover, the code of conduct, a `.gitignore`, and CI workflows that run the build with the publication profile, the docs lint, and an OSV dependency scan. The POM's `scm` and `issueManagement` now name this repository, and the `NOTICE` names this project.
